# Zubrilka — приложение

До переименования называлось Frontend Quiz. Внутренние имена хранилищ (`frontend-quiz` в IndexedDB, ключи
`fq.*` в localStorage, метка формата файла заметок) остались прежними, чтобы у пользователей не пропали данные.

Тренажёр по базе вопросов из корня репозитория. React 19, TypeScript, Vite, CSS Modules.

## Запуск

Из корня репозитория:

```
pnpm install     — один раз
pnpm build       — собрать базу в dist/questions.json (без неё приложению нечего показывать)
pnpm dev         — локальный сервер, адрес появится в терминале (обычно http://localhost:5173)
pnpm app:build   — собрать базу и приложение в app/dist, как это делает GitHub
```

Чтобы открыть с телефона в той же Wi-Fi сети: `pnpm -F frontend-quiz-app dev --host`, затем адрес
вида `http://192.168.x.x:5173` из терминала.

В режиме разработки приложение берёт локальный `dist/questions.json`. Поправил YAML — выполни `pnpm build`
и нажми в приложении «Обновить» (или очисти данные сайта): база с устройства сама не перечитывается.

## Что умеет

- Работает без интернета и ставится на телефон (PWA). Service Worker кэширует файлы приложения при первом
  открытии; база в этот кэш не входит, она в IndexedDB. Кнопка «Установить приложение» на главной появляется,
  когда Chrome готов установить. Новая версия приложения включается только по кнопке «Перезапустить» в плашке
  сверху, чтобы не оборвать сессию. В режиме разработки (`pnpm dev`) Service Worker не работает.
- База скачивается при первом открытии и хранится на устройстве (IndexedDB). Дальше приложение в сеть не
  ходит, пока не нажать «Обновить» на главной; после обновления видно, сколько вопросов добавилось,
  исправилось и удалилось.
- Выбор тем, подтем и уровней, сессия на 10, 20, 30 вопросов или бесконечная. Последний выбор запоминается.
- Варианты перемешиваются. После ответа — пояснение к каждому варианту и общее объяснение механизма.
- Итог сессии: счёт, разбивка по темам, список ошибок, «прорешать ошибки ещё раз». Итог живёт в памяти
  и никуда не сохраняется.
- Вопросы с несколькими правильными ответами: галочки, кнопка «Ответить», засчитывается только выбор всех
  правильных без лишних. После ответа у вариантов пометки «Верно», «Пропущен», «Лишний».
- Свои наборы: YAML-файл добавляется по https-ссылке (сайт должен разрешать CORS) или с устройства в «Моих наборах», тренируется отдельно от основной
  базы со своими фильтрами, обновляется и удаляется. Формат — в `examples/README.md`.
- Режим обучения: у набора с уроками (раздел `lessons` в YAML) — кнопка «Учиться», оглавление, урок с таблицами,
  картинками и блоками кода, затем вопросы урока по порядку и «Продолжить обучение» с того же места. Ответы
  в обучении не пишутся в ленту ответов: статистика, «Ошибки», «Новые» и достижения от них не меняются. Отметки
  «освоен» (все вопросы урока верно за один проход) и место в курсе — в своей базе IndexedDB `frontend-quiz-lessons`,
  сбрасываются в оглавлении курса.
- Озвучка уроков: у урока с полем `audio` — «Слушать урок», плеер на всех экранах (свёрнутый — значок с кольцом
  прогресса в правом нижнем углу, над нижней панелью кнопок — над ней; развёрнутый — шторка), играет при выключенном
  экране, кнопки на экране блокировки (Media Session). Место в аудио — в прогрессе уроков. Аудио курса скачивается
  на телефон кнопкой в оглавлении (хранилище Cache API `lesson-audio`, Service Worker отдаёт его кусками для
  перемотки); лишнее аудио стирается само. Устройство и план — `plans/audio-mode.md`.
- Заметки к вопросам в IndexedDB, экран «Мои заметки», выгрузка и загрузка файлом.
- Четыре темы оформления (Аврора, Графит, Терминал, Закат), выбор запоминается на устройстве.
- Клавиатура: 1–4 — ответ, Enter или → — дальше. Системная «Назад» возвращает на предыдущий экран;
  посреди сессии с ответами — показывает итог.

## Вход по паролю

Перед приложением — экран пароля (`features/access/AccessGate.tsx`), чтобы случайный человек по ссылке не
прошёл дальше. Это не защита данных: проверка в браузере, база и репозиторий открыты. В `src/config.ts`
хранится SHA-256 пароля; задаётся командой `pnpm password <пароль>` из корня, `--off` выключает вход. На
устройстве запоминается отпечаток введённого пароля, поэтому смена пароля снова показывает всем экран входа.
В режиме разработки (`pnpm dev`) пароль не спрашивается. В страницу добавлен `noindex` для поисковиков.

## Инструкция для пользователей

Два раздела внутри приложения: «Как пользоваться» (`screens/help/HelpScreen.tsx`) и «Свои наборы вопросов»
(`SetsHelpScreen.tsx`). Прямые ссылки, которые можно отправить: `…/frontend-quiz/#help` и `…/#help-sets` —
открывают раздел поверх главной. При первом открытии на главной показывается плашка «Впервые здесь?».
Адреса репозитория, примера набора и Issues — в `src/config.ts`.

Названия кнопок в инструкции совпадают с подписями на экранах: переименовал кнопку — поправь и инструкцию.

## Устройство

```
src/
  app/          корень: загрузка базы, стек экранов, связанный с историей браузера
  data/         типы базы, загрузка questions.json, копия базы в IndexedDB, сравнение версий
  features/
    session/    фильтры, пул вопросов, очередь сессии
    notes/      заметки: IndexedDB, контекст, файл выгрузки; ключ заметки — набор + id вопроса
    sets/       свои наборы: https-ссылка (GitHub/gist → сырой файл), снисходительный разбор YAML, IndexedDB, контекст
    lessons/    прогресс уроков: отметки «освоен», место в курсе и в озвучке (IndexedDB, контекст), логика оглавления
    audio/      плеер озвучки уроков: один <audio> на приложение, Media Session, сворачиваемый плеер
    pwa/        регистрация Service Worker и плашка новой версии, кнопка установки, постоянное хранилище
  screens/      экраны: home, sets (список и экран набора), training (общий блок фильтров), session,
                question (карточка вопроса), summary, review, notes, lessons (оглавление, урок, вопросы урока)
  shared/       общие компоненты (стекло, кнопки, чипы, панель, разметка, подсветка кода) и утилиты
  theme/        список тем и панель выбора
  styles/       themes.css — переменные четырёх тем, global.css — сброс
```

Цвета, радиусы и шрифты компоненты берут только из переменных `styles/themes.css`. Тема включается атрибутом
`data-theme` на `<html>`. Скрипт в `index.html` ставит сохранённую тему до запуска React, чтобы при открытии
не мелькала тема по умолчанию.

Размер шрифта — только из шкалы в начале `styles/themes.css`: шесть переменных `--font-size-*` по роли текста
(подпись, пояснение, мелкий текст, основной, заголовок, крупный заголовок); строчный код — в `em`. Это проверяет
stylelint при сборке приложения (отдельно — `pnpm -F frontend-quiz-app lint:css`). Если в теме с широким шрифтом
надпись перестаёт влезать, тема уменьшает размер у себя — правилом `:global([data-theme="…"])` в модуле компонента.
Комментарии «подогнано» и «перенос допустим» в CSS — решения автора: подогнанное не увеличивать.

Иконки в `public/icons/` нарисованы из той же SVG, что и `favicon.svg`; маскируемая — с фоном во весь квадрат,
Android сам обрезает её под форму иконок системы.

В `public/demos/` лежат демо-страницы курсов — отдельные маленькие страницы с нарочно встроенными проблемами,
чтобы ученик открыл их в Chrome вместе с DevTools (сейчас — курс «Браузер изнутри», `demos/browser/`). Сборка
копирует их на сайт как есть. Service Worker их не кэширует и не подменяет на приложение (`globIgnores`
и `navigateFallbackDenylist` в `vite.config.ts`, проверка — в наборе e2e `pwa`).

Тексты вопросов рендерит react-markdown: разрешены только `код`, **жирный**, курсив и ссылки, HTML из текста
не исполняется. Код подсвечивает prism-react-renderer; SCSS и HTTP подключены из prismjs.

Текст уроков рисует отдельный компонент `screens/lessons/LessonMarkdown.tsx`: плюс заголовки, таблицы и сноски
(remark-gfm), цитаты, картинки и блоки кода. HTML в нём тоже не исполняется. Картинку можно открыть на весь
экран и увеличить — `shared/ui/ImageViewer.tsx`. Экраны уроков вместе с ним —
отдельный файл сборки (`React.lazy` в `app/QuizApp.tsx`): он грузится, только когда открывают уроки, и лежит
в кэше Service Worker вместе с остальным приложением. Картинки уроков с чужих сайтов кэшируются при просмотре,
если сайт разрешает CORS (`lesson-images` в `vite.config.ts`).

## Формат файла заметок

```json
{
  "format": "frontend-quiz-notes",
  "version": 1,
  "exportedAt": "2026-10-12T08:00:00.000Z",
  "notes": [
    {
      "key": "builtin:javascript-event-loop-002",
      "setId": "builtin",
      "questionId": "javascript-event-loop-002",
      "text": "Текст заметки",
      "updatedAt": 1760256000000,
      "snapshot": { "question": "…", "topicTitle": "JavaScript", "subtopicTitle": "Event loop", "level": "middle" }
    }
  ]
}
```

При загрузке файла заметки сливаются: побеждает более свежая по `updatedAt`.

Сейчас приложение пишет версию 3: кроме `notes` в файле `answers` (лента ответов), `bookmarks` (закладки) и
`lessons` (прогресс уроков по наборам). Метка `format` прежняя, массив `notes` есть всегда — так старые версии
приложения новую копию принимают и незнакомые поля пропускают. Прогресс уроков при загрузке дописывается:
урок освоен, если освоен хоть в одной копии, место в курсе — из более свежей. Поле с отметками называется `read`
исторически: раньше отметка была «прочитан», старые отметки засчитаны как «освоен».
