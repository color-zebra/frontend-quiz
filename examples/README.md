# Свой набор вопросов для Zubrilka

Подробная пошаговая инструкция — в самом приложении: https://color-zebra.github.io/frontend-quiz/#help-sets.
Здесь — краткая выжимка формата.

Набор — один YAML-файл. В приложении: «Мои наборы» → вставить ссылку на файл → «Добавить». Подойдёт прямая
https-ссылка на сам файл с сайта, который разрешает чтение с других сайтов (CORS): GitHub и gist, Bitbucket,
jsDelivr, unpkg. Для GitHub и gist можно дать обычную ссылку на страницу файла (`github.com/…/blob/…`) —
приложение само возьмёт сырой файл. GitLab, Codeberg и Pastebin файл браузеру не отдают. Пример — [sample-set.yaml](sample-set.yaml).

Файл можно и не выкладывать: «Мои наборы» → «Загрузить файл с устройства». Такой набор обновляется повторной
загрузкой файла с тем же именем.

Набор хранится на устройстве и работает без интернета. Поправил файл на GitHub — нажми «Обновить» у набора.

## Формат

```yaml
title: Мой набор                  # название; если нет — имя файла
questions:
  - id: algo-001                  # уникален внутри набора; к нему привязаны заметки — не меняй его
    topic: Сортировки             # необязательно: тема внутри набора, по ней фильтр на экране набора
    subtopic: Быстрая сортировка  # необязательно: подтема внутри темы
    level: middle                 # junior | middle | senior
    question: |
      Текст вопроса. Можно `код`, **жирный** и списки строками «- пункт».
    code: |                       # необязательно: код к вопросу
      [3, 1, 2].sort()
    codeLang: js                  # html | css | scss | js | ts | jsx | tsx | http | json | text
    options:
      - text: 'Вариант'
        why: 'Почему он неверен'
      - text: 'Правильный вариант'
        correct: true
        why: 'Почему он верен'
    explanation: |               # необязательно: как это устроено
      Общее объяснение.
    links:                        # необязательно, только https
      - https://developer.mozilla.org/...
```

## Несколько правильных ответов

Отметь `correct: true` у нескольких вариантов — приложение покажет галочки и подсказку «Выберите все
подходящие варианты». Ответ засчитывается, только если выбраны все правильные и ни одного лишнего.

Чтобы вид вопроса не подсказывал, что правильных несколько, добавь вопросу `multiple: true`: тогда галочки
будут и при одном правильном варианте.

## Устный набор

Устные вопросы — без вариантов: человек отвечает сам, открывает эталон и оценивает себя («знал», «частично»,
«не знал»). Набор целиком либо тестовый, либо устный: строка `kind: speech` в начале файла делает его устным.
Пример — [speech-sample.yaml](speech-sample.yaml).

```yaml
title: Устный набор
kind: speech
questions:
  - id: s-001
    topic: React                    # необязательно
    level: middle
    question: |
      Зачем элементам списка нужен key?
    answer: |                       # эталонный ответ
      По key React сопоставляет элементы между рендерами…
    points:                         # необязательно — тезисы для самопроверки
      - Ключ сопоставляет элементы между рендерами
```

Тестовый вопрос в устном наборе (и наоборот) приложение пропустит и объяснит причину в «Что пропущено».

## Уроки (режим обучения)

В тестовый набор можно добавить уроки — связный текст, который читают до вопросов. Тогда на экране набора
появится кнопка «Учиться»: урок → его вопросы по порядку, с разбором после каждого → следующий урок. Есть
оглавление, переход к предыдущему уроку и «Продолжить обучение» с того места, где остановился. Ответы в режиме
обучения не попадают в статистику, «Ошибки», «Новые» и достижения. Пример —
[lessons-sample.yaml](lessons-sample.yaml).

```yaml
title: Системный дизайн — основы
lessons:
  - id: req-intro                   # обязателен, уникален среди уроков; к нему привязана отметка «прочитан»
    topic: Постановка задачи        # необязательно: раздел оглавления
    subtopic: Требования            # необязательно: вопросы урока — тестовые вопросы этой темы и подтемы
    title: Как выяснять требования  # обязателен
    body: |                         # обязателен: текст урока
      ## Зачем это нужно
      …
    questions: [sd-req-001, sd-req-002]   # необязательно: какие вопросы после урока и в каком порядке
questions:
  - id: sd-req-001
    topic: Постановка задачи
    subtopic: Требования
    …
```

- **Порядок уроков — порядок в файле.** Подряд идущие уроки с одинаковым `topic` в оглавлении — один раздел.
- **Вопросы после урока:** если есть `questions` — именно они и в этом порядке; иначе, если есть `subtopic`, —
  вопросы с теми же `topic` и `subtopic` в порядке файла; иначе вопросов нет, после урока сразу следующий.
  Урок без `topic` ищет вопросы так же, как вопрос без темы получает тему: тему файла или «Все вопросы».
  Неизвестный id в `questions` и подтема без вопросов попадут в замечания «Что поправить в файле».
- **Вопросы в наборе нужны обязательно,** хотя бы один: набор из одних уроков не откроется ни в новой, ни в
  старой версии приложения. Отдельный урок без вопросов — можно.
- **Урок без `id`, `title` или `body` и урок с повторным `id`** приложение пропустит и покажет в «Что пропущено»
  как «урок req-intro». В устном наборе (`kind: speech`) уроки не работают — будет замечание.
- **id урока не меняй:** к нему привязаны отметка «прочитан» и место, где человек остановился.
- **Старые версии приложения** уроки не видят, а вопросы набора у них работают как обычно. Набор, добавленный
  до появления уроков, покажет их после «Обновить» (по ссылке) или повторной загрузки файла.

### Текст урока

`body` — Markdown: заголовки `##`–`####` (`#` показывается как `##`: у урока уже есть заголовок), абзацы,
**жирный**, *курсив*, ~~зачёркнутый~~, списки (в том числе вложенные и `- [x]` с галочкой), цитаты `>` — они
выглядят как блок «важно», линия `---`, ссылки, `код`, блоки кода с подсветкой (```` ```js ````, `ts`, `tsx`,
`html`, `css`, `json`, `http`, `yaml`…), таблицы и сноски `[^1]`. HTML-теги не работают и показываются как текст.

Широкая таблица на телефоне прокручивается вбок внутри своей рамки.

**Картинки:** `![что на картинке](images/schema.png "подпись")`. Текст в квадратных скобках обязателен — его
видят, если картинка не загрузилась. Адрес — `https://…` или путь **относительно файла набора**: для набора по
ссылке `…/custom-sets/course.yaml` путь `images/schema.png` ведёт в `…/custom-sets/images/schema.png`.
Относительные пути лучше: картинки переедут вместе с набором. У набора, загруженного файлом с устройства,
относительный путь не от чего считать — такие картинки нужно давать полной ссылкой.

Увиденную картинку приложение сохраняет для работы без интернета, если сайт с ней разрешает чтение с других
сайтов (CORS): GitHub (raw.githubusercontent.com) разрешает. С остальных сайтов картинки показываются только
с интернетом. Сохранённая копия живёт до 30 дней, поэтому исправленную картинку клади **под новым именем** —
иначе те, кто её уже видел, ещё долго будут видеть старую.

## Что приложение пропустит

Проверка формата — на совести автора. Вопрос без `id`, текста, понятного `level`, вариантов или хотя бы
одного `correct: true` приложение пропустит и после загрузки скажет, сколько пропущено. Вопрос с уже
встречавшимся `id` тоже пропускается. Если файл не читается как YAML или в нём нет списка `questions`,
набор не добавится. Что приложение пропускает в уроках — в разделе «Уроки» выше.

## Файл из основной базы

Приложение понимает и формат файлов основной базы (`topic` и `subtopic` в начале файла, `questions` ниже),
поэтому любую подтему из `questions/` можно добавить отдельным набором по ссылке.
