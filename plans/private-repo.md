# Закрыть исходники и базу — бесплатно, без смены адреса

Цель: спрятать код и базу вопросов, пока проект не дорос до монетизации, не платя ни за что и не теряя данные
пользователей. Решения приняты 2026-10-14, к работе не приступали.

## Почему не другой хостинг

- **GitHub Pages из приватного репозитория** — только на платном GitHub Pro. Платить пока не хотим.
- **Netlify** — бесплатно около 20 выкладок в месяц (300 кредитов, выкладка — 15), по исчерпании сайт ставится на
  паузу до следующего месяца. У нас бывает больше 20 коммитов в месяц.
- **Cloudflare Pages** — с июня 2025 российские провайдеры режут соединения с Cloudflare после 16 КБ; так же —
  Hetzner и DigitalOcean. Аудитория русскоязычная.
- **Любой новый адрес** (Netlify, Vercel и т. п.) обнуляет у людей прогресс, ошибки, заметки, закладки и
  достижения: всё это хранится в браузере и привязано к адресу сайта. Перенос — только через резервную копию.

## Этап 1. Два репозитория

- **Исходники** — в приватный репозиторий (переименовать `frontend-quiz` → `frontend-quiz-src` или как решим).
- **Готовый сайт** — в новый публичный репозиторий с прежним именем `frontend-quiz`: только собранные файлы,
  ветка `gh-pages`, каждая сборка — один коммит без истории (чтобы по истории нельзя было смотреть, как росла
  база). Адрес `color-zebra.github.io/frontend-quiz` не меняется — у людей всё на месте, установленное
  приложение обновляется как раньше.
- **Деплой** — GitHub Actions приватного репозитория, как сейчас, но готовую `app/dist` кладёт в публичный
  репозиторий по ключу развёртывания (deploy key только на этот репозиторий). Бесплатных минут Actions для
  приватного — 2000 в месяц, наш деплой — минуты две.

Ссылки в приложении на репозиторий с исходниками станут 404:
- **«Не согласен»** у вопроса основной базы — открывает новую задачу (issue) в публичном репозитории с заполненным
  заголовком («Не согласен с вопросом» + начало текста) и описанием (id, тема, подтема, начало вопроса,
  «Что не так:»). Весь вопрос не влезет — у адреса ссылки есть предел длины. Фраза «Буду рад пулл реквесту!»
  меняется: пулл-реквест прислать уже нельзя.
- **«Сообщить об ошибке»** — на задачи публичного репозитория.
- **Пример набора** («Подставить ссылку на пример») — кладём в сам сайт рядом с приложением.
- **Не забыть: каталог готовых наборов** («Мои наборы» → «Готовые наборы»: WebSocket и Module Federation).
  Ссылки прописаны прямо в `custom-sets/catalog.yaml` и ведут на `raw` файлы
  `custom-sets/*.yaml` в репозитории с исходниками. После закрытия кнопка «Добавить» будет отвечать «Файл не
  найден», а «Обновить» у уже добавленных — тоже. Как и пример, наборы из каталога надо класть в сам сайт при сборке
  (плагин каталога в `app/vite.config.ts` уже читает эти файлы) и поменять ссылки в каталоге. Камни:
  - id набора — отпечаток ссылки, а к нему привязаны прогресс и заметки. У тех, кто добавил набор до переезда, он со
    ссылкой на сайт не совпадёт: каталог должен узнавать и старую ссылку на GitHub (иначе предложит добавить второй
    такой же), а «Обновить» у старого набора перестанет работать — подсказать удалить его и добавить заново
    (статистика по набору начнётся с нуля, заметки останутся в «Моих заметках»);
  - на локальном сервере сайт открыт по `http://`, а ссылки с `http` приложение не принимает — для своих файлов
    сайта эту проверку обойти;
  - сейчас сайт пересобирает только правка `custom-sets/catalog.yaml` (правило в `deploy.yml`); если наборы
    поедут на сайт, правка набора из каталога тоже должна его пересобирать — иначе на сайте останется старая версия;
  - **картинки уроков переезжают вместе с наборами.** В уроках картинки указаны путём относительно файла набора
    (`images/schema.png` рядом с `course.yaml`). Кладёшь набор на сайт — клади туда же и его папку с картинками,
    в той же раскладке, иначе в уроках вместо картинок будут заглушки. То же для примера
    `examples/lessons-sample.yaml` и его `examples/images/`. На своём сайте CORS не нужен, но для офлайна есть
    камень: кэш картинок уроков (`lesson-images` в `app/vite.config.ts`) сейчас ловит только чужие сайты. Свои
    картинки сайта попадут в офлайн, только если их возьмёт общий кэш приложения (`globPatterns`: сейчас там
    `png` и `svg`, но не `jpg` и `webp`) — проверить и при необходимости расширить правило.
- Свои наборы не меняются: у набора по ссылке — файл автора, у набора из файла — шутка «сам составлял».
- **Известная ошибка, чинить при переезде:** «Не согласен» строит путь к файлу по подтеме, а после слияния вопросы
  `questions/react/rendering.yaml` (подтема `internals`) ведёт в `internals.yaml` на неверную строку. Файл брать из
  id (`<тема>-<имя файла>-NNN`, у устных с `speech-`) и указывать в тексте задачи; тест — на вопрос из rendering.

Порядок для пользователя (инструкцию по нажатиям расписать при старте). Переезд — на выходных 17–18 октября 2026,
если к тому времени всё готово; делать одним заходом, вечером.
1. Проверить форки — после закрытия чужие форки остаются публичными навсегда.
2. Переименовать репозиторий в `frontend-quiz-src`.
3. **Сразу же, до создания нового репозитория** — поменять у себя адрес удалённого репозитория:
   `git remote set-url origin https://github.com/color-zebra/frontend-quiz-src.git`, проверить `git remote -v`.
   Пока нового `frontend-quiz` нет, GitHub перенаправляет старый адрес на переименованный. Как только он создан,
   старый адрес ведёт уже в **публичный репозиторий с сайтом**, и `git push` по нему выложит туда все исходники,
   базу в YAML и чужие наборы у всех на виду.
4. Создать пустой публичный `frontend-quiz`.
5. Создать ключ (`ssh-keygen`): открытую половину — в Deploy keys публичного (с записью), закрытую — в Secrets
   приватного.
6. Включить Pages в публичном из ветки `gh-pages`, запустить деплой вручную, проверить сайт по старому адресу.
7. Сделать исходники приватными.

**Сайт лежит между шагами 2 и 6.** После переименования GitHub переносит сайт на `…/frontend-quiz-src/`, и старый
адрес отдаёт 404, пока в новый `frontend-quiz` не придёт первый деплой. Обычно несколько минут. Установленное
приложение работает из кэша; кто откроет сайт впервые в это окно — увидит 404.

**Адрес сайта не меняется** (`color-zebra.github.io/frontend-quiz/`): он собирается из имени аккаунта и имени
репозитория, а публичный репозиторий получает прежнее имя. Поменяют адрес (и обнулят у людей данные в браузере —
перенос только через резервную копию) лишь переименование аккаунта `color-zebra` или своё доменное имя. Домен,
если понадобится, лучше заводить, пока пользователей мало.

Решено: приватный репозиторий — `frontend-quiz-src`; вместо «Буду рад пулл реквесту!» — «Не согласен с
формулировкой или ответом? Напиши, что не так, — поправлю» (ссылка открывает новую задачу).

Как готовить код, чтобы его можно было закоммитить заранее и ничего не сломать до переезда: деплой выбирает цель
сам — нет ключа в секретах → Pages текущего репозитория, как сейчас; есть ключ → публичный репозиторий. Ссылки на
задачи `color-zebra/frontend-quiz/issues` работают и до переезда, и после. Пример набора — отдавать с сайта
(в e2e «Мои наборы» обновление набора тогда проверять на другой ссылке, не на примере).

## Отдельный репозиторий для базы — не сейчас

Решено 2026-10-14: база остаётся вместе с приложением в приватном репозитории. Защиты отдельный репозиторий не
добавляет (оба приватные; от посторонних защищает шифрование из этапа 2), а цена — второй ключ доступа для сборки,
два деплоя в один сайт, формат базы как договор между двумя репозиториями. Переезжать, когда появится повод:
открываем код приложения при закрытой базе или появляется соавтор базы. План двух репозиториев этому не мешает —
`frontend-quiz-src` станет репозиторием приложения. Пока держим базу легко отделимой: `questions/`, `speech/`,
`topics.yaml`, схемы и скрипты проверки — отдельно от `app/`.

## Этап 2. Шифрование базы паролем (отложено)

Без него закрытие скрывает код и YAML-исходники, но не саму базу: `questions.json` со всеми ответами и
объяснениями лежит на сайте и в публичном репозитории открыто, пароль на входе от скачивания по прямому адресу не
защищает. И всё, что было в репозитории до закрытия, уже могли скопировать.

Как:
- При сборке база шифруется ключом из пароля (PBKDF2 → AES-GCM, Web Crypto). Пароль — в секретах приватного
  репозитория, а не в коде; `pnpm password` в нынешнем виде уходит.
- На сайт и в публичный репозиторий попадает только шифр. Приложение после ввода пароля расшифровывает базу в
  браузере, дальше всё как сейчас, в том числе без интернета.
- Смена пароля = пересборка, все вводят пароль заново (как и сейчас).
- Пароль — не словарный: шифр лежит открыто, короткий пароль подбирается перебором.

Что даёт: базу не скачать одним файлом, не прочесть на GitHub и поисковику. Чего не даёт: пароль общий — кто его
знает, может вытащить базу и выложить. Защита от «своих» — только вход по почте с сервером (этап монетизации:
бесплатная часть базы — витрина, платная — по входу; почты россиян — на серверах в России).
